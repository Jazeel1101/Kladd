# Session capture on macOS

`SessionCaptureDarwin` runs one `kladd-capture session` per recording (`native/Sources/KladdCapture/Session.swift`). It writes the live files of the session folder (`packages/domain/src/SessionFolder.ts`). Starting and stopping work like `record` (`docs/internals/screen-capture.md`).

- **One clock.** t = 0 is the host-clock time of the first video frame, the clock ScreenCaptureKit stamps frames with. The microphone has its own clock, so t = 0 is converted to it, and a microphone that starts late is padded with silence. Players ignore the empty edit AVAssetWriter would insert, and speech would drift against `t`.
- **AVAssetWriter, not `SCRecordingOutput`.** `record` uses `SCRecordingOutput`; the session writes frames itself so it can control the bitrate and use that clock. The files are fragmented every 10 s, so after a crash `screen.mp4` and `audio.m4a` still play up to the last fragment. ScreenCaptureKit sends no frames while the screen is still, so the last frame is appended again at stop and the video lasts until `stop`.
- **The video keeps running.** A stream that stops on its own is started again into the same file every 5 s until it works. Everything else logs to stderr and carries on. While the Mac is locked, ScreenCaptureKit lists no display, so a session can't start then.
- **`frame` events are written with the JPEG**, before OCR, so a crash during OCR still leaves the keyframe on the timeline. `ocr` names the `.txt` OCR will write; it is missing when OCR failed or had not finished. At stop, OCR gets 10 s more. Vision's first accurate-mode call on a Mac loads its model, which can take 30–100 s.
- **Stop keeps watching files for 1.5 s.** fseventsd hands a change over up to about a second late, and `FSEventStreamFlushSync` does not hurry it; changes that arrive then get the `stop` event's `t`.
- **Privacy lists come from domain** as JSON arguments (`--exclude-apps`, `--deny-paths`). The helper adds Kladd's data dir itself, as `<dir>/../..`, because the folder is `<dataDir>/recordings/<session>`. The filter is rebuilt when an excluded app starts, since ScreenCaptureKit only excludes apps that are running; from its launch until the stream accepts a filter that leaves it out, no video frames or keyframes are written, so the video freezes briefly. The titles of excluded apps are left out of `focus` events.
- **Microphone.** The first session asks; the answer counts from the next session. macOS asks on behalf of Kladd, the responsible app, so Kladd's `Info.plist` needs `NSMicrophoneUsageDescription` (`apps/desktop/electron-builder.yml`). With the lid closed, a MacBook's built-in microphone delivers no samples, so `audio.m4a` is missing even though `start.microphone` is true.
