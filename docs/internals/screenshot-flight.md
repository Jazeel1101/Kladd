# Screenshot flight

⌃⇧C (`apps/desktop/src/main/screenshotShortcut.ts`) runs `Screenshots.take` (`packages/core/src/screenshot/Screenshots.ts`): it saves a PNG of the main display and sets the tray's `flying` screenshot. It doesn't touch the logging overlay. The `flight` window then plays the animation (`apps/ui/src/screenshot/ScreenshotFlight.tsx`), and a tray slides out of the pill's flat side to take it in (`apps/ui/src/pill/useScreenshotIntake.tsx`): the screenshot flies into the tray's slot, the pill holds it a beat, then the tray slides back in. The pill draws the screenshot inside the tray, clipped by the tray's own outline, so the shutting tray hides it without the screenshot changing, and throws it away once the tray has shut. The pill's own shape doesn't change.

- **Coordinates.** The flight window covers `OverlayWindows.mainDisplay` (menu bar included), so the screenshot first covers the screen 1:1 and the screen seems to freeze. It flies to `landingIn(slot, display)` in screen points: the tray's full height, against the pill, so the tray can be as long as the screenshot is wide. Docked, the tray opens away from the wall; floating, toward the side of the pill with more of the screen. The slot is the most room the tray can open to and the side the pill is on (`apps/ui/src/pill/intake.ts`), and it moves with the pill inside its window, so the pill reports it with `SetScreenshotSlot` (`apps/ui/src/pill/useNotchDrag.ts`) whenever it comes to rest; before the first report, a screenshot is attached without a flight. When it arrives, the UI calls `LandScreenshot`: main attaches it, which the pill sees and draws its own copy under the flight's, and hides the flight window 100 ms later, so neither window is ever without it. Main does that only for the screenshot still flying, one at a time with `take`, so a flight that ends late can't hide a newer one.
- **Frame rate.** The screenshot is full resolution, so only `translate`, `scale` and `opacity` are animated, which the compositor runs without repainting it. Animating `border-radius`, `box-shadow` or a clip repaints the whole screen-sized layer every frame: it drops frames, and Chromium logs "tile memory limits exceeded" and leaves parts of the screenshot undrawn. Keep the screenshot the only screen-sized layer with content. The first frame is painted before the animation clock starts, so the GPU upload doesn't eat its start.
- **Images.** The sandboxed UI loads files as `kladd-screenshot://<id>` (`apps/desktop/src/main/screenshotProtocol.ts`), and `apps/ui/index.html` allows that scheme in `img-src`. Only a UUID `ScreenshotId` resolves to a file.
- **Window.** `flight` is an `effect` row in the window table: click-through, no shadow, above the pill at screen-saver level, and not throttled while hidden, so its next flight starts at once. It is loaded at startup.
- **Motion.** Springs become CSS `linear()` easings (`apps/ui/src/screenshot/spring.ts`) and run in the Web Animations API, off the main thread. X and Y travel use different springs, so the path curves. With reduced motion turned on, the screenshot lands at once with no animation.
