# Overlay placement

How the logging overlay ends up next to where the user writes. Entry point: `LoggingOverlay.open` in `packages/core/src/logging/LoggingOverlay.ts`, called when a recording stops or from "Show logging overlay" in the pill menu (for trying adapters).

1. **Focus.** The `FocusTracker` port returns a `FocusSnapshot`: front app, window frame and title, focused element frame and caret rect. `FocusTrackerDarwin` runs `kladd-capture focus` (`packages/platform-darwin/native/Sources/KladdCapture/Focus.swift`), which reads `NSWorkspace` and Accessibility (`AXFocusedWindow`, `AXFocusedUIElement`, `AXBoundsForRange` on the selected range) and prints JSON. The pill menu makes Kladd the active app, so when Kladd is in front the helper reads the app owning the topmost normal window instead; AX still answers for it in the background. If the helper breaks, the overlay opens as if nothing were known.
2. **Any rect can be null.** Electron and Chromium apps (Slack, Notion, VS Code) usually report no element or caret, canvas editors report no element, and without Accessibility permission only the front app is known.
3. **Permission.** Accessibility is Kladd's permission, like screen recording (`docs/internals/screen-capture.md`). Once a recording has started, `Recordings.start` asks for it in the background with `askForAccessibility`, via PermissionFlow's Accessibility pane, one prompt at a time. It is optional, so recording never waits for it.
4. **Anchor and target.** `adapterFor` picks the adapter for the front app's bundle id, else `Generic`. The adapter returns the anchor rect (or null), and the `WritingTarget`: app and document names, by default the app name and window title.
5. **Placement.** `placeOverlay` in `packages/domain/src/Placement.ts` is pure: right of the anchor, flipped left when that doesn't fit, clamped to the display's work area. With no anchor, `placeWithoutAnchor` centres it at the right screen edge.
6. **Showing.** Core publishes a `LoggingOverlayInfo` (target, adapter id, anchored or not), which the overlay UI reads through the `WatchLoggingOverlay` Rpc. Then it calls the `OverlayWindows` port, implemented in `apps/desktop/src/main/windows.ts` because only desktop may import Electron. Overlays are `panel` windows shown with `showInactive()`, so the writing app keeps keyboard focus. Moving a window that is already visible is animated (`setBounds(bounds, true)`).

AX and Electron both use points with the origin at the top-left of the main display, so rects pass through unchanged. Displays left of or above the main one have negative coordinates.
